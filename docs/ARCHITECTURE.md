# Architecture and data boundaries

`Model.cs` defines 47 action kinds, editable step properties and schema-v1 serialization. Saves write a unique adjacent temporary file and replace the destination atomically. Documents are limited to 16 MB and 100,000 steps. Invalid numeric ranges, versions, colors and null/unknown actions fail validation.

`Engine.cs` expands includes with a 16-level bound, cycle detection and independent label namespaces. A validation pass constructs IF/ELSE and REPEAT pair maps. Crossed/unclosed blocks, duplicate/missing labels and misplaced BREAK fail before input injection. A jump cannot enter an inactive loop. Finite playback has a ten-million-dispatch budget. Explicit infinite playback bypasses that budget, with a yield every 32 control dispatches. IF scopes are reconciled on block ends and jumps, restoring outer image results. The runner owns cancellation/pause state and always requests synthesized-input release in finally.

`WindowsHost.cs` implements a Windows host behind IHost. Tests use FakeHost rather than sending input. Real playback tracks its synthesized held keys/buttons. Text uses Unicode SendInput instead of modifying the clipboard. SetClipboard is the explicit clipboard-writing action. Searches and image conditions run on background tasks with cancellation checks; their buffers use 32-bit normalized rows. Screen regions use the virtual desktop including negative coordinates. Tolerance is the allowed absolute difference per RGB channel, inclusive; zero is exact. The recorder filters injected events and MacroExecute's own input, excludes the currently assigned global action shortcuts and saved-macro bindings, throttles movement samples, and records delays with Stopwatch. Hooks exist only during a user-started recording session.

`Integrations.cs` exports MacroExecute's own executable with a SHA-256-checked JSON payload and length marker. Re-export replaces an existing overlay. This checksum detects corruption; it is not a digital signature or trust guarantee. Includes are flattened before UI export, but image templates are embedded; external executables and other files remain explicit dependencies. Windows schedules use the platform COM API, interactive-user logon, least privilege, unique task IDs and the `--run` CLI. Scheduling is only performed after the user presses Create schedule.

RunCSharp uses the platform CodeDOM provider with explicit framework references and a newly generated temporary executable. It runs in a separate child process with a timeout and cancellation cleanup. There is no in-process user reflection contract. This does not sandbox user code or control child-spawned descendants; compilation is not forcibly preempted, but timeout/cancellation stops awaiting it and prevents launch; cleanup is deferred until the compilation task completes. The deadline includes compilation. Trusted scripts only. The test suite does not compile/run user scripts.

`MainForm.cs` owns the original WinForms workbench, undo/redo, document state, point/image capture and hotkeys. The desktop host is never active merely because a file is opened. Play uses a three-second focus countdown; the configured Stop shortcut must be registered before recording or playback can start. UI smoke mode avoids registering global hotkeys. A Message step intentionally waits for acknowledgement; dismiss its dialog before continuing/stopping the interpreter.

`SelfTests.cs` verifies serialization, structural flow, include isolation, cancellation, ABI sizes, bitmap matching, portable payloads and quoting. `--smoke` and `--headless-preview` render hidden workbenches without showing or activating forms, recording/playback or registering hotkeys. The isolated suite injects a synthetic IImageDesktop into the real WindowsHost for image/click tests; it sends no desktop input. The separate opt-in --desktop-test uses a guarded foreground test window for real capture and clicks. No isolated test installs global hooks, changes the clipboard or creates a schedule.

There is no telemetry, update downloader, licensing server, embedded signing key or bundled third-party application code. Workflows can explicitly launch programs, open URLs or modify files; review those steps before running a workflow from another person.

`ImageActions.cs` defines the injectable desktop boundary, embedded PNG templates, scoped match state, pointer modes and pause-aware polling. `EditorTools.cs` implements block ranges/copying and original GDI icons. `StepEditor.cs` provides guided action dialogs. Existing schema-v1 numeric action IDs are retained; new actions are appended and missing properties use constructor defaults.

`Shortcuts.cs` separates remappable global controls from in-app commands. A registrar abstraction supports transactional re-registration and conflict rollback without reserving real keys in tests. `ShortcutForm.cs` captures chords while real global registrations are suspended. `MainForm.Commands.cs` centralizes dispatch, shortcut hints, theme switching and context actions. Preferences retain older file bindings, add theme/action settings and save atomically.

`UiTheme.cs` and `ThemedControls.cs` provide shared light/dark palettes, menus, list selection, tab drawing and readable disabled buttons. Themes are applied to app dialogs as they are built or rebuilt. Original icons are recolored and their bitmaps retained until image-list handles are finished with them. `HeadlessUi.cs` creates hidden handles solely for offscreen WM_PRINT rendering and performs no desktop input or screen capture. `SettingsTests.cs` covers configuration, injected registration and headless UI behavior.

`Behavior.cs` supplies explicit text methods, keyboard/clipboard injection boundaries and tolerance interpretation. `InputPermissions.cs` reads integrity/UIAccess tokens for actionable input diagnostics; the administrator restart remains an explicit UI action. Portable payload reads account for PE certificate tables; exports clear obsolete signing metadata. See COMPATIBILITY.md for contracts and acceptance limits.

`ClipboardCondition.cs` implements pure literal string conditions and bounded copy/read waits. `ITextClipboard.ReadText` and the injected keyboard interface isolate execution from the system clipboard in tests. CopySelection sends Ctrl+C and optionally waits for a changed clipboard containing text; it does not synthesize copied data or restore the old clipboard. One text snapshot is used per condition. The clipboard probe runs its fake host on a pool task to avoid waiting on an unpumped WinForms synchronization context. `StepEditor.Clipboard.cs` supplies the rule editor and local sample tester; sample text is independent of the real clipboard.
